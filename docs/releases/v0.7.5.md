Fixes Chat/Responses templating, native streaming, cancellation and resource
ownership for desktop inference while preserving the media-capable direct API.
The llama.cpp pin remains `95b8b8ec1a9e77bcc7b3fb04da82c9f35cb12a79`.

- All message requests apply the model template once. Raw completions retain
  their independent semantics; incremental UTF-8 decoding handles token splits.
- Direct clients keep model weights resident and serialize requests with a fresh
  context. HTTP uses upstream slots/KV checkpoints through an owning worker.
  Direct KV prefix reuse is not implemented.
- Streaming preserves ordered text/reasoning/tool fragments, finish reasons and
  usage. DONE-only streams fail. Disconnects cancel native work; teardown awaits
  cleanup. Queues, task retention and collector resources are bounded.
- C ABI/thread exception boundaries return structured errors. Budgets include
  actual template/media tokens and output reservation; overflow is rejected early.
- Direct sampling accepts each token once; safe adapters contain grammar and
  allocation exceptions. The existing direct Gemma4 grammar omission remains;
  tool templates/parsing are tested, schema-constrained generation is not claimed.
- Linux/Windows share packaged library names and validate shim symbols. Required
  unavailable accelerators fail explicitly; diagnostic limitations remain visible.
  The CLI accepts native Windows drive paths.

Verified with the pinned Gemma-4-E2B Q4_K_M fixture on Linux CPU and NVIDIA GB10
CUDA/Vulkan. Actual CUDA and Vulkan prompts of **31741 / 64509 / 130045 tokens** passed
the 32K/64K/128K tiers, including three-position retrieval, multi-turn cache reuse,
cancellation and recovery. This is specific source-build/hardware evidence.
CPU 32K/64K passed; CPU 128K is tracked separately. Windows long windows
remain unverified. Native context initialization is not a 128K inference
claim. Q8 KV, direct KV reuse and RoPE extension are not claimed.

Interactive CPU examples use batch 256/microbatch 128. Measured disconnect-to-next
response was 1.66–1.68 seconds on the tested CPU; upstream 2048/512 defaults took
20.23–21.13 seconds. Cancellation waits for safe batch boundaries and has no
hardware-independent latency guarantee.
The default-name consumer smoke uses affinity-aware threads and 32/32; it verifies
fresh partial prefill before disconnect and retains the 15-second recovery gate.

consumer checks; accelerator build success is not long-window acceptance.
